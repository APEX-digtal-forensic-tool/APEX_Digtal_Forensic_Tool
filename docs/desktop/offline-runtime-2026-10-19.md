# API 없이 사용하는 로컬 분석 구성

PR #26 후속 작업. main 병합은 담당자가 진행한다.

## 이번 변경

| 기능 | 최신 Windows 설치 파일 | 별도로 필요한 것 |
| --- | --- | --- |
| 영상·음성 메타데이터 | ffprobe와 공유 DLL 포함, 앱 내부 경로 자동 탐색 | 분석할 원본 파일 |
| 영상 프레임 | FFmpeg 포함, 파일 트리 내용 뷰어 또는 미디어 아티팩트 검사기 → 영상 프레임 보기 → 요청 시각 입력 (파일 트리 진입점은 [후속 수정](review-followups-2026-10-20.md) FE-02에서 연결) | 분석할 원본 파일 |
| OCR | 기존 RapidOCR 실행기 및 기본/한국어 모델 포함 | 이미지. Tesseract는 선택적 대체 분석기 |
| STT | Faster Whisper 실행기와 **Whisper base 다국어 모델** 포함, 미설정 시 자동 선택 | 음성. 더 큰 사용자 지정 모델을 쓸 때만 폴더 선택 |
| 고급 DPAPI | Impacket 및 Cryptodome를 런타임에 포함, 기존 오프라인 엔진 사용 | 대상 PC의 MasterKey·SID·암호/NT 해시 등 해당 방식에 필요한 자료 |
| 원격 AI | 기존 준비·검토·정책 경로 유지 | 제공자 주소·모델·API 키가 필요하므로 이번 외부 연결 범위에서 제외 |

기본 로컬 분석에는 로그인, AI API 키, 사용자 PC의 Python 설치, FFmpeg PATH 등록,
STT 모델의 별도 다운로드가 필요하지 않다. 복호화 라이브러리를 포함했다는 것은
비밀번호나 키 없이 모든 암호화 자료를 해제한다는 뜻이 아니다. DPAPI의 기존 코어/CLI
입력 흐름을 유지하며 새로운 비밀값 표시 화면을 추가하지 않았다.

Tesseract와 whisper.cpp는 선택적 대체 분석기다. 기본 RapidOCR/Faster Whisper와 동일한
역할의 분석기를 모두 중복 설치하지 않는다. 이 대체 분석기를 명시적으로 선택할 때는
해당 실행기와 맞는 모델이 필요하다. macOS에는 다국어 STT와 DPAPI를 포함하지만
이번 FFmpeg/ffprobe 실행 파일 번들은 요청한 **Windows x64**용이다.

## 설치·개발·빌드

- 설치 파일: 설정 → 로컬 OCR·음성 인식에서 기본 모델, FFmpeg/ffprobe, DPAPI 준비 상태 확인.
- 기존 사용자 지정 모델은 유지한다. 기본 모델로 돌아가려면 **기본 내장 모델로 복원 → 분석기 설정 저장**.
- 소스 개발: `docs/desktop/README.md`의 전체 extras 설치 후
  `uv run --no-sync python tools/prepare_desktop_assets.py` 실행. Windows에서 도구와 모델을
  준비한다. 다른 OS에서 Windows 자산만 준비할 때 `--windows`를 사용할 수 있으나
  Windows 실행 파일의 실행/패키징은 Windows 호스트에서 해야 한다.
- `tools/build_desktop_runtime.py`와 PowerShell 빌더가 자산 준비 및 런타임 복사를 자동 수행한다.
- 최초 빌드에는 공개 모델/도구 다운로드를 위한 인터넷과 충분한 디스크 공간이 필요하다.
  분석할 증거는 이 다운로드에 사용하지 않는다. 설치 후 추론에는 로컬 파일만 사용한다.
- 모델 revision, 개별 파일 SHA-256/크기, FFmpeg 배포 tag와 SHA-256을
  `tools/desktop-assets.lock.json`에 고정했다. 손상/다른 버전이면 빌드를 중단한다.
  ZIP 경로 탈출·링크·과대 압축 해제도 거부한다.
- 바이너리/가중치는 Git 소스에 넣지 않고 빌드 산출물에 포함한다.
  `runtime/assets/asset-manifest.json`과 `runtime/assets/notices`, FFmpeg 원본 배포의
  LICENSE/docs에서 출처와 고지를 확인할 수 있다.

## 영상 연결 보완

기존 `_ffmpeg_sample_frame`은 직접 단위 검사만 있었고 화면에서 호출되지 않았다.
`VideoInspectionService` → `media.video` 로컬 API → Electron allowlist →
`VideoInspector`를 연결했다. 파일 노드와 MEDIA_VIDEO 아티팩트를 모두 지원한다.

사건 범위와 파일 출처를 확인한 뒤 최대 512 MiB의 논리 파일을 임시 사본으로 읽는다.
이미지 내부 파일도 공통 읽기 경로를 사용한다. 사본 SHA-256, 파일 revision,
요청 시각, 파생 PNG SHA-256을 함께 반환한다. 기존 아티팩트의 원본 해시와 다르면 거부한다.
화면 선택 변경 후 이전 요청의 결과가 나타나지 않도록 처리했다.

FFmpeg는 한 프레임, 최대 1536 px 화면 미리보기, 15초 디코딩 제한을 사용한다.
API 최대 크기는 2048 px, 결과 상한은 8 MiB다. 원본 한 프레임은 최대 33,177,600픽셀(8K UHD)로 제한한다. 요청 시각 이후 디코딩되는 프레임이며
원본 프레임 번호/정확한 PTS를 계산했다고 표시하지 않는다. 출력은 미리보기이며
원본 프레임 내보내기나 영상 내용에 대한 AI 해석 기능을 의미하지 않는다.
FFmpeg/ffprobe에는 로컬 프로토콜·컨테이너 허용 목록을 적용하여 증거를 가장한
재생 목록이 외부 URL이나 별도 로컬 파일을 참조하지 못하도록 했다.

## 검증 및 정확도

첫 Windows 네이티브 STT 검사에서 작업 조회가 HTTP 409로 실패했다. 확인 결과
서비스를 열 때마다 기본 분석기 상태와 도구 목록을 다시 저장하며, 도구 목록의 쓰기 트랜잭션을 열린 채 유지하고 있었다.
긴 음성 추론 중 다른 요청도 같은 쓰기 잠금을 요구하여 충돌할 수 있었다.
기본 상태와 도구 목록 등록을 초기화 시 한 번 수행하고 즉시 커밋하도록 수정했으며,
일반 요청/작업 연결은 등록을 반복하지 않는다. 다른 쓰기 연결이 열린 동안의
서비스 조회와 추론 중 작업 상태 조회를 회귀 검사로 추가했다.

- 실제 합성 MP4를 로컬 HTTP API로 읽어 해상도·PNG·파생 해시·원본 불변 확인.
  다른 사건의 파일, 영상 끝 이후 요청, 재생 목록 입력을 거부하는 회귀 검사 포함.
- 기본 다국어 모델로 공개 영어 JFK 샘플의 실제 문장과 구간 추출 확인.
- [Google FLEURS](https://huggingface.co/datasets/google/fleurs), `ko_kr/test`, id `1883`,
  CC-BY-4.0 한국어 음성 약 12.48초를 실제 추론했다. 파일 SHA-256:
  `e6bc095e55046de927d7c937f036f96ebb506570648ad9ae7c6576febfc4746a`.
  한국어와 시간 구간을 반환했으며 숫자·내용 대부분을 인식했지만 정답의 **다리 밑**을
  **다리미**로 잘못 인식했다. 한 샘플의 실행 검증이며 전체 정확도 벤치마크가 아니다.
- STT/OCR은 검토 후보다. 음질·발화·모델 크기에 따라 오인식할 수 있어 자동으로 관찰 사실로 승격하지 않는다.
- 이전에 Impacket 미설치로 건너뛰던 DPAPI 시험도 라이브러리를 설치하고 실행했다.
- Windows 네이티브 빌드 검증은 FFmpeg 번들의 실제 영상 생성/추출, ffprobe 정보,
  내장 STT 모델의 `HF_HUB_OFFLINE=1` 추론, DPAPI 모듈 로딩, 기존 E01/VHD/VHDX·OCR 검사를 필수로 한다.
- 전체 Python/프론트 테스트 수와 플랫폼별 빌드 결과는 해당 커밋의 PR 본문에 기록한다.

기존의 차등 디스크 부모 체인, 암호화 볼륨 전반, 조각난 파일 자동 재조립 등의
지원 한계는 [기능 연결 문서](../engine/completed-connections-2026-10-19.md)와 같다.
의존성 내장이 이러한 미지원 형식까지 해결했다는 의미는 아니다.
