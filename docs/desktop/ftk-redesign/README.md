# FTK Imager 기반 APEX 작업 화면 리디자인

## 조사 근거

- [Exterro FTK Imager 공식 제품 페이지](https://www.exterro.com/digital-forensics-software/ftk-imager)
- [FTK Imager 8.2 User Guide](https://d1kpmuwb7gvu1i.cloudfront.net/Imager/8.2/Exterro%20FTK%20Imager%208.2%20-%20User%20Guide%20.pdf): 인쇄 쪽 번호 16–24의 도킹 패널·도구 모음·Evidence Tree·File List·Properties·Viewer 설명, PDF 28·53쪽의 실제 앱 화면을 확인했다. 가이드 안에는 이전 버전의 화면도 포함되어 있다.

FTK의 주요 탐색 방식은 증거 계층을 왼쪽 위에 유지하고, 선택한 디렉터리의 파일을 오른쪽 위에 표시하는 것이다. 속성은 왼쪽 아래, 파일 내용은 오른쪽 아래에서 확인한다. 텍스트와 Hex 표시를 전환하고 구분선을 움직여 작업 면적을 조절한다.

APEX에는 이 정보 구조를 적용했다. FTK의 Windows 테마와 고유 아이콘을 복제하지 않고, 사용자가 지정한 어두운 테마·APEX 로고·Astryx 아이콘 진입점·Material 파일 아이콘을 유지했다. 기존 인수인계 문서의 레이아웃은 권장안으로 명시되어 있으므로 이번 사용자 요청을 우선하되, Core 계약과 데이터 거버넌스 요구는 유지한다.

## 기존 화면에서 확인한 문제

1. 전체 사건의 증거 트리가 없고, 파일 시스템 화면에서 선택한 증거의 폴더만 표시된다.
2. 세로 주 메뉴와 하위 메뉴가 탐색 너비와 높이를 함께 소비한다.
3. 속성과 내용이 하나의 검사기에 섞여 파일의 위치·상태·내용을 동시에 비교하기 어렵다.
4. 원본 보기에 진입하고 별도 읽기 버튼을 눌러야 내용이 나오며 Hex 데이터에 주소·ASCII 열이 없다.
5. 폴더를 목록에서 열 때 트리의 펼침 상태와 경로 이동이 충분히 연결되어 있지 않다.

## 구현

- 상단 사건/증거 선택과 작업 상태, 공통 작업 도구 모음, 가로 분석 화면 탭.
- 항상 표시되는 증거 트리: 모든 등록 증거, 실제 Core가 반환한 루트, 폴더와 일반 파일의 지연 로딩, 커서 기반 추가 로딩, 선택 경로 펼침 및 스크롤. 일반 파일은 펼침 버튼 없는 말단 항목이며, 선택하면 부모 폴더 목록·속성·내용 뷰어가 함께 연결된다. 목록 응답이 늦게 도착해도 트리에서 선택한 파일은 유지한다.
- 파일 목록과 속성 패널, 경로 버튼 및 상위 폴더 이동. 파일 목록의 Enter와 더블클릭으로 디렉터리 진입.
- 독립된 내용 뷰어: Preview, Text, Hex, 메타데이터. Hex는 오프셋·16바이트 열·ASCII 열로 표시.
- `view.raw-read`가 허용된 항목의 바이트를 최대 4 KiB씩 조회. 10진수/16진수 오프셋과 이전·다음 범위 이동. 증거 데이터는 HTML로 실행하지 않는다.
- 지원 이미지에는 기존 `media.inspect` 미리보기 및 비트 분석 연결. 메타데이터·원본 출처·경고·인용 원본 조회·보고서 인용 수집 유지.
- 포인터/키보드 패널 크기 조절과 배치 초기화. 증거 전환·컴포넌트 해제 이후 도착하는 비동기 응답은 무시.
- 실제 Core 연결과 합성 데모를 상태 표시줄에서 구분.

새 컴포넌트는 `frontend/src/workbench/`에 분리했다. 기존 분석·검색·후보 검토·보관 이력·보고서·설정 화면의 데이터 계약과 작업 동작은 유지했다.

## 확인 범위

- TypeScript 검사 및 Vite 프로덕션 웹 빌드 통과. 번들 500 kB 초과 경고는 남아 있다.
- 브라우저에서 합성 데모 사건의 증거 전환, 폴더 진입/상위 이동, 트리 동기화, 메타데이터, Text/Hex, `0x10` 오프셋, 패널 키보드 조절/초기화, 다른 분석 탭에서 탐색 복귀를 확인했다.
- 기본 1333×986 및 1024×768에서 확인. 작은 창에서 활성 증거가 가려지던 문제를 수정하고 재확인했다.
- 자동 테스트 스위트는 실행하지 않았다. 실제 디스크 이미지·네이티브 앱 패키징·Windows/macOS 실기기 회귀 검증과 실제 이미지 미리보기 검증은 이번 확인 범위에 포함하지 않았다.
- 개발 서버는 `VITE_APEX_DEMO=1 npm run dev:web`로 실행했으며, 데모는 실제 증거를 읽지 않는다.

이번 작업은 레이아웃과 탐색/표시 개선이다. 디스크 획득, 메모리 수집, 이미지 마운트, FTK 고유 형식 복호화 또는 MCP 연결을 새로 구현한 것은 아니다.
