## 재검토 중 추가 보완: 설정 교체 실패

손상된 설정을 먼저 백업 경로로 이동하면, 이후 새 파일 교체가 실패할 때 활성 설정 파일이 사라진다. 다음 조회가 이를 최초 실행으로 해석해 기본값을 적용할 수 있다.

저장 경로에서는 손상 설정을 **복사**해서 보존하고 원래 파일은 성공적인 원자 교체 때까지 남긴다. 교체 실패 후에도 원문이 활성 경로에 그대로 있고 `JSON_SYNTAX` 진단이 유지되는지 검사한다. 사용자가 명시적으로 초기화한 경우에는 기존처럼 백업으로 이동하고 기본값을 적용한다.

## 작업 이력 API 계약

작업 결과가 성공했더라도 이력 파일 저장이 실패하면 다음처럼 응답한다.

```json
{
  "status": "SUCCEEDED",
  "error": null,
  "result": { "output_path": "derived.bin" },
  "receipt_error": {
    "code": "TASK_RECEIPT_NOT_SAVED",
    "message_key": "error.task_receipt_not_saved",
    "retryable": true
  },
  "actions": []
}
```

- `status`는 실제 분석 결과다. 저장 실패를 이유로 이미 완료된 분석이나 생성된 결과를 실패로 덮어쓰지 않는다.
- `error`는 원래 분석 오류다. 분석 자체가 실패했다면 해당 오류와 `receipt_error`를 모두 유지한다.
- `receipt_error`는 저장되지 않은 상태를 알리는 일시적 메모리 필드다. 저장이 성공하면 지워지며 이력 파일에는 넣지 않는다.
- 기본 `tasks.list`는 쓰기를 재시도하지 않는다. 1.6초 UI 폴링이 디스크 장애 중 반복 쓰기를 만들지 않는다.
- `tasks.list`에 `{ "case_id": "...", "retry_receipts": true }`를 전달하면 해당 사건에 미저장 기록이 있을 때 전체 이력 스냅샷 저장을 **한 번** 시도한다. 분석 작업은 다시 실행하지 않는다.
- 다른 사건에만 저장 경고가 있는 경우 해당 요청은 재저장을 유발하지 않는다.
- 앱 종료 시 미저장 기록이 있으면 한 번 더 저장한다. 계속 저장할 수 없다면 재시작 때 마지막 저장 상태를 읽을 수밖에 없으므로 UI가 종료 전 이 위험을 설명한다.
- 기존 요청의 `retry_receipts` 생략은 호환된다. 새로운 엔드포인트나 Electron 허용 목록 변경은 없다.

## 설정·인증·AI의 오류 처리 범위

- 설정 잠금은 단일 로컬 API 프로세스 내 스레드 동시성을 보호한다. 여러 프로세스가 같은 데이터 디렉터리를 동시에 쓰는 운영 방식까지 보장하지 않는다.
- Windows에서 열린 임시 파일을 바로 교체하지 않도록 파일을 닫은 뒤 `replace`한다.
- JWKS 최상위 문서가 잘못되면 기존 네트워크 오류 처리와 마찬가지로 이미 보유한 캐시를 유지한다. 캐시가 없는 검증기는 토큰을 거부한다.
- 정상 형태의 `{ "keys": [] }`는 권위 있는 빈 키 집합으로 보고 캐시를 비운다. 혼합 목록에서는 유효한 항목만 사용한다. TTL·알 수 없는 kid 재조회 제한·서명/issuer/audience 검증은 유지한다.
- AI 진단에는 원본 설정 문자열·URL·자격 증명을 포함하지 않는다. `AI_CONFIGURATION_INVALID`와 설정 출처만 노출한다.
- AI 실행 설정 검증을 느슨하게 하지 않는다. 등록된 정상 파일을 선택한 상태에서도 잘못된 설정이면 실행 오류가 나고 제공자 호출은 0회다.

## 보고서 연동 검사에서 확인한 계약

`tests/desktop/test_local_api.py::test_report_copy_preserves_rich_sections_scope_and_export`는 모의 gateway가 아니라 실제 FastAPI와 Core 서비스를 사용한다.

1. 합성 증거 두 개와 보고서 초안을 생성한다.
2. 표 데이터, AI 출처 표시, 부분 분석, 오래된 결과 사유, 경고, coverage를 가진 버전을 저장한다.
3. 편집기의 전송 구조로 새 버전을 만들고 빈 범위 또는 여러 증거 범위와 기존 섹션 속성이 보존되는지 확인한다.
4. 여러 증거 버전은 검토 제출→섹션 채택→검토 완료→승인→HTML 내보내기를 수행한다.
5. 증거 없는 초안은 보존하지만 보관 이력이 없어 승인·내보내기가 거부되는 기존 보호 규칙을 확인한다.
6. 원래 버전의 내용과 증거 범위가 변경되지 않았는지 확인한다.

Core는 증거 ID를 정렬하고 필요한 경고를 보강할 수 있다. 따라서 증거 범위는 집합으로 비교하고, 복사할 섹션의 기준은 Core가 실제 반환한 원본 버전으로 잡는다.

독립 재현 검사의 작업 이력 조건은 예전의 `error != null`만 요구하던 검사에서 별도 `receipt_error`도 확인하도록 조정했다. 실제 분석 성공을 실패로 변경하지 않기 위한 계약이며, UI 경고·수동 재저장·실행 횟수·재시작 상태는 저장소의 새 회귀 검사로 추가 검증했다.

Python에서 건너뛴 5개는 실제 STT 모델/영·한 음성 자료, 실제 한국어 OCR 자료, pyvhdi, qemu-img, pyewf 환경 검사다. 실제 모델과 해당 도구가 없는 Linux 환경에서 실행되지 않았으며 통과로 계산하지 않았다. 기존 passlib의 Python crypt 폐기 예정 경고 1개가 있다.

빌드에는 기존 단일 번들 크기 경고가 있다. 빌드 실패는 아니며 이번 수정에서 번들 분할 구조를 변경하지 않는다.
