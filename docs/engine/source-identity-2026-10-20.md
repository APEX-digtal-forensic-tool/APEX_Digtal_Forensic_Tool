# 이미지 원본 식별 검증

## 수정한 문제

2026-10-20 머지 후 점검의 ENG-01을 수정한다. 기존 TSK 파일 읽기는 한 번의 읽기 전후만 비교했다. 등록/색인 후 읽기 시작 전에 이미지 본문이 바뀌면 같은 inode·크기를 가진 기존 node로 변경된 바이트를 반환할 수 있었다.

등록 시 물리 원본 기준을 영속화하고 실제 내용 읽기에 그 기준을 적용한다. 원본을 쓰기 가능하게 열거나 변경된 파일을 기존 색인의 정상 내용으로 채택하지 않는다.

## 적용 경로

- `EvidenceManager.register_evidence`: 원본 식별 정보를 해시/컨테이너 검사 전에 캡처하고 이후에도 동일한지 확인한다. 기존 Evidence metadata JSON에 저장하므로 별도 DB 테이블 마이그레이션은 없다.
- `source_identity.py`: 물리 경로, 크기, 나노초 수정/변경 시각, device, inode를 비교한다. symlink/reparse point 및 없어진 원본을 거부한다. Windows에서는 `stat`과 `fstat`의 ctime 의미가 다를 수 있으므로 Path.stat끼리 비교한다.
- `GuardedEvidenceReader`: 기존 RAW/DD/IMG 및 E01/VHD/VHDX reader를 공통 factory에서 감싼다. 열기 전후·범위 읽기 전후·정상 context 종료에서 확인한다. 파티션 열거도 같은 읽기 경계를 통과한다.
- `PyTskFileSystemProvider.open_file`: 파일 본문·ADS·삭제 파일 복구에서 시작/종료 시 기준을 확인한다. TSK가 캐시로 처리한 읽기도 종료 검사를 우회하지 못한다.
- raw range, slack, 물리 extent 복구, 시그니처 카빙도 공통 factory를 사용한다. 상위 이미지 미리보기·아티팩트 분석·OCR/STT 임시 사본·AI 본문 발췌는 기존 content 경로의 검사를 받는다.
- 실패는 `RAW_SOURCE_CHANGED`로 전달한다. 로컬 API의 raw.read는 오류 응답을 반환하고 변경된 본문을 성공 응답으로 내보내지 않는다.
- 색인 초기화에서 원본 검사·root 생성·선택 범위 준비가 실패하면 Core 작업과 색인 작업·coverage를 `FAILED`로 저장하고 오류·종료 시각을 남긴다. 준비가 끝나지 않은 큐는 재개 가능한 checkpoint로 취급하지 않는다. 원인을 해결한 뒤 새 색인 작업을 실행해야 하며, 기존 부분 완료·일시정지·취소 작업의 정상 재개는 유지한다.

E01은 첫 파일뿐 아니라 discover된 세그먼트 전체의 구성과 식별 정보를 비교한다. 추가·삭제·교체·수정된 후속 세그먼트를 거부하고, 같은 번호의 대소문자 중복 세그먼트도 거부한다. 지원되는 EWF 이름 범위는 기존 reader의 `.E01` 형식을 따른다.

## 이전 버전에서 등록한 사건

이전 Evidence 레코드에는 `source_identity`가 없다. 현재 파일의 stat을 기존 증거의 신뢰 기준으로 자동 채택하지 않는다.

1. 단일 물리 파일인 RAW/DD/IMG/VHD/VHDX 또는 단일 세그먼트 E01은 기존 **SHA256 해시 계산** 작업을 한 번 실행한다.
2. 계산한 SHA-256과 크기가 **등록 당시 fingerprint**와 같고, 해싱 전후 원본 식별 정보가 변하지 않았을 때만 기준을 저장한다. 가장 최근에 새로 계산한 임의 해시를 신뢰 기준으로 삼지 않는다.
3. 일치하지 않거나 fingerprint가 없으면 기준을 추가하지 않고 작업 warning에 `SOURCE_IDENTITY_REQUIRED` 사유를 남긴다. 파일 내용 읽기는 계속 거부된다.
4. 예전 다중 세그먼트 E01은 첫 세그먼트 해시만으로 다른 세그먼트의 과거 동일성을 입증할 수 없다. 자동 보완하지 않는다. 원본 세트를 확인한 뒤 별도 증거로 다시 등록하고 색인한다. 기존 사건 기록은 삭제하지 않는다.

기준 정보가 이미 있는 증거는 해시 재계산으로 그 기준을 바꾸지 않는다. 원본을 의도적으로 다른 파일로 바꿨다면 새 증거로 등록해야 하며 기존 source/index를 그대로 재사용하면 안 된다. 기존 논리 파일/디렉터리의 색인 기반 내용 검사 정책은 변경하지 않는다.

## 성능과 보장 범위

- 작은 범위 읽기는 물리 원본 메타데이터를 검사한다. 매 읽기마다 이미지 전체 SHA-256을 계산하지 않는다.
- 등록 때와 명시적 해시 작업에서 전체 파일 해시를 계산하는 기존 동작은 유지한다. 예전 단일 파일 기준 보완은 그 명시적 작업의 계산 결과를 재사용한다.
- 이 검사는 변경 감지이며 암호학적 바이트별 불변성 보증은 아니다. OS가 노출하는 파일 식별자/시간/크기까지 보존하거나 조작하는 공격은 메타데이터만으로 완전히 검출할 수 없다. 정식 전체 소스 무결성 검증과 운영상의 원본 보호가 별도로 필요하다.
- 세그먼트 검사는 세그먼트 수에 비례한다. 대형 실제 이미지의 성능 벤치마크를 이번 단위 시험 결과로 대체하지 않는다.
- 실제 FAT/NTFS 및 저장소의 E01/VHD/VHDX fixture를 사용한다. 다중 E01 세그먼트 변경 시험은 물리 체인 검사를 분리해 검증하며, 모든 현장 EWF 변종의 디코딩 검증이라는 뜻은 아니다.

## 회귀 검증

`tests/unit/test_image_source_identity.py`와 `tests/desktop/test_image_source_identity_api.py`는 다음을 확인한다.

- 등록/색인 후 본문 변경, DB 재연결 후 거부, 정상 파일 내용 읽기.
- 실제 E01/VHD/VHDX의 등록 기준 비교, 동일 크기/mtime 파일 교체.
- 읽기 도중 변경, TSK 캐시 scope 종료 검사, 열기 실패 시 reader 정리.
- 후속 E01 세그먼트 수정/누락/추가/교체 및 중복 번호.
- ADS 읽기/내보내기, raw/slack/삭제 파일 복구/카빙의 변경 원본 거부.
- 등록 중 원본 변경 시 레코드를 저장하지 않음.
- 이전 단일 파일의 원래 SHA-256 일치 때만 기준 보완, 다중 세그먼트의 불완전한 기준 채택 금지, 기존 기준 재설정 금지.
- 작은 내용 읽기가 전체 source_fingerprint 계산을 호출하지 않음.
- 로컬 raw.read HTTP 오류와 본문 미노출.
- 변경/누락/기준값 없는 이미지의 색인 거부가 DB 재연결 후에도 FAILED·원래 오류·종료 시각으로 남고, 불완전한 초기화 작업의 재개는 명확히 거부됨. 제공자 예외와 선택 범위 준비 실패도 같은 상태로 정리됨.

Desktop CI는 새 Core 시험을 Windows와 macOS 선택 검사에 포함한다. 새 실행의 실제 통과/실패 상태는 PR checks에서 확인한다.
