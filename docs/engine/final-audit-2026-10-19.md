  증거 전환, 분석 도중 입력 변경을 별도 재현했다.

처음 전체 검사는 770개가 통과했지만 아래 추가 재현 검사는 실패했다.
따라서 기존 테스트 통과만으로 누락이나 결함이 없다고 판단하지 않았다.

## 추가 발견 및 수정

| 항목 | 재현된 문제 | 수정 |
| --- | --- | --- |
| 일반 파일의 변경 감지 | 인덱싱 이후 파일이 늘어나면 이전 크기만 읽고 성공하거나, 읽는 중 변경된 바이트를 섞어서 반환할 수 있음 | 저장된 크기·수정 시각·파일 식별정보를 확인하고, 읽기 전후 열린 핸들과 경로의 상태를 비교. 짧은 범위 읽기도 오류 처리. Hex·이미지·영상의 공통 읽기 경계에 반영 |
| OCR/STT 입력 격리 | 이미지 내부 파일은 사본을 사용했으나 일반 파일은 `materialize`에서 원본 경로를 그대로 반환. 사전 취소도 이 분기에서 검사하지 않음 | 일반 파일도 제한된 임시 사본으로 제공하고 취소를 먼저 확인. 사본을 수정하는 합성 파서가 원본을 바꾸지 못하며 종료 시 삭제되는 것을 검증 |
| 작업 등록 실패 | 작업 기록 저장 실패 또는 실행기 종료 후 제출 실패가 실행될 수 없는 QUEUED 기록과 취소 토큰을 남김 | 실패한 등록의 메모리 기록·토큰을 제거. 제출 실패 시 이미 저장한 기록도 정리. 반복 저장 실패가 대기열 16칸을 소모하지 않는지 검증 |

| ADS 읽기 화면 | 읽기 도중 스트림과 오프셋을 바꿀 수 있어 표시된 선택값과 반환된 결과가 어긋날 수 있음 | 처리 중 해당 입력을 잠그고, 새 오프셋 편집 시 기존 결과를 비움. 빈 오프셋을 0으로 처리하지 않음 |

일반 파일의 상태 비교는 매번 전체 파일을 해싱하는 검사가 아니다. 운영체제의 파일
식별정보·수정 시각 비교와 읽은 바이트의 해시를 사용한다. 모든 메타데이터를 보존한

## 후속 Windows CI 실패 수정

위 로컬 검증 이후 `f6838806`의 Windows Desktop CI에서 **7 failed, 81 passed,
6 skipped**가 발생했다. macOS ARM/Intel 및 MCP 검사는 성공했다. Linux 테스트
통과가 Windows 동작 확인을 대신하지 못한 회귀 오류다.

- Python 3.12 Windows에서 경로 `stat()`와 열린 핸들 `fstat()`의 `ctime` 의미가
  다를 수 있는데 이를 서로 비교해 변경되지 않은 파일을 `RAW_SOURCE_CHANGED`로
  거부했다. AI 입력 준비·STT 임시 사본·Hex 읽기·이미지 검사에서 실패했다.
- Windows `DirEntry.stat()`는 inode/device/nlink를 0으로 반환한다. 이를 실제
  파일 식별값으로 저장·비교하면 디렉터리 내부 파일에서도 잘못된 변경 오류가 발생한다.
- 수정: 경로 상태는 경로끼리, 핸들 상태는 핸들끼리 읽기 전후 비교한다. 경로와
  핸들 사이에서는 식별값·크기·수정 시각을 비교한다. `ctime` 검사를 삭제하지 않았다.
- 디렉터리 인덱싱은 링크를 따라가지 않는 경로 `stat`으로 실제 식별정보를 기록한다.
  기존 Windows 인덱스의 inode/device가 모두 0인 경우에만 알 수 없는 식별값으로
  처리하며, 크기·수정 시각 및 현재 읽기 전후 식별정보 검사는 유지한다.
- Windows의 시간값 차이, 기존 0 식별값 인덱스, 디렉터리 식별값 저장 오류를
  재현한 검사 **3개가 수정 전 실패**했고 수정 후 통과했다. 읽는 중 핸들의
  `ctime`만 바뀌어도 계속 거부하는 검사도 추가했다.
- 원본 무결성 회귀 검사 11개를 Windows/macOS Desktop CI에 포함하고 해당 테스트
  파일 변경도 워크플로 실행 조건에 추가했다. 관련 로컬 검사 **35개 통과**,
  Ruff·mypy 통과. 최종 전체 테스트와 네이티브 CI 결과는 PR 본문에 기록한다.

참고: [Python 3.12 os 문서](https://docs.python.org/3.12/library/os.html#os.DirEntry.stat),
[CPython Windows stat 구현](https://github.com/python/cpython/blob/3.12/Modules/posixmodule.c).

## 남아 있는 검증/지원 한계

- 실제 원격 AI 제공자 호출은 API 설정 제공 후 검증할 항목이다. 현재는 준비·가림·검토·정책·가짜 전송 경로를 검사한다.
- 차등 VHD/VHDX 부모 체인, 암호화 볼륨 전반, 조각난 파일 자동 재조립은 기존 지원 범위에 포함되지 않는다.
- STT/OCR은 검토 후보이며 한국어 전체 정확도를 보증하지 않는다. 네이티브 음성 추론의 취소는 즉시 강제 종료 방식이 아니다.
- 선택적 Tesseract 실자료 및 대체 pyewf/pyvhdi/qemu-img 검사는 해당 자료·도구가 없으면 건너뛴다. 기본 RapidOCR/Dissect 경로와 구분한다.
- 로컬 release gate의 선택적 AJV CLI·호스트 자료 없는 runtime 검사는 제한으로 표시한다. 프론트 빌드의 AJV 계약 생성은 별도로 실행한다.

[기능 연결 문서](completed-connections-2026-10-19.md)를 따른다.
